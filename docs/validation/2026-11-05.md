## 동시 요청 회귀 테스트 (PostgreSQL)

- 서로 다른 두 계정이 동일 좌석 점유: 한 계정만 성공, 잔여 99석.
- 한 계정이 8개 탭에서 4석 자동배정: 최종 활성 점유 4석, 잔여 96석.
- 같은 주문 동시 취소: 한 요청만 상태 변경, 잔여 100석, 점유 좌석 없음.
- 기존 전체 자동 테스트 통과.

## 실행 서버 HTTP 확인

- 앱 재시작 전후 동일 쿠키로 로그인 유지.
- 잘못된 예약 정보 요청이 정상 안내 페이지로 이동.
- 자동 4석 → 자동 4석 → 수동 4석 재선택, 전체 취소 및 정리 통과.
- `scripts/audit-reservations.sql`로 범위 밖 잔여수, 활성 좌석 중복, 시간대 중복, 잔여수 불일치, 좌석 점유 불일치, 취소 결제의 활성 예약을 조회.

## 한계와 후속 작업

- 실제 토스 인증 및 브라우저 뒤로가기는 최신 코드로 수동 확인이 필요하다. HTTP/모의 API 검증과 구분한다.
- 로그인 시도 제한, 관리자 재처리 화면, DB 마이그레이션 및 클라우드 배포 검증은 아직 남아 있다.
- 다중 탭에서는 가장 최근 결제 진입이 이전 미결제 선택을 대체한다. 이전 탭의 오래된 주문은 승인할 수 없다.
- 신규 조회는 현재 시점의 불일치만 확인한다. 향후 모든 장애가 없다는 보장은 아니다.
